## 2. Identified Issues

### [High] Console Missing AdminApiClient Registration
- **Observation:** The `InitializeDatabaseCommand` in `GesFer.Console` manually constructs a `ServiceCollection` but fails to register `IAdminApiClient` and `IConfiguration`.
- **Impact:** The `DbInitializer.EnsureAdminUserAndSmokeTestAsync` method relies on `IAdminApiClient` to validate that the Admin user's Company exists in the Admin system. Because the service is missing, `services.GetService<IAdminApiClient>()` returns `null`, causing the check to be silently skipped. This can lead to a corrupted database state where the Product DB references a non-existent Company in Admin, causing runtime failures when users try to interact with Customers (which triggers validation against Admin API).
- **Root Cause:** Incomplete manual DI setup in `InitializeDatabaseCommand.cs`.

### [Medium] Silent Failure in Smoke Test
- **Observation:** `DbInitializer.EnsureAdminUserAndSmokeTestAsync` checks `if (adminClient != null)` but has no `else` block to warn if the client is missing.
- **Impact:** Developers/Operators are unaware that the validation is not running.

## 3. Action Plan

1.  **Fix Console DI:** Register `IConfiguration` and `IAdminApiClient` (via `AddHttpClient`) in `InitializeDatabaseCommand.cs`.
2.  **Enhance Logging:** Add a warning log in `DbInitializer` when `IAdminApiClient` is missing.
3.  **Verify:** Ensure Console builds and tests pass.

## 4. Expected Outcome

The Console initialization process will now robustly validate the Admin/Product integrity, preventing "silent" configuration errors that block user interaction with Clients/Customers later.
